# ABSTRACT

Well-trained deep learning (DL) models are widely used in various fields and recognized as valuable intellectual property. However, most existing efforts to fully exploit their value either require users to upload input data to provide machine learning services, which raises serious privacy concerns, or deploy DL models on the user side, resulting in a loss of control over the models. While a few active model authorization methods protect the model from unauthorized users, they cannot prevent the model from being redistributed or abused by authorized users. To address the urgent need to efficiently protect both model confidentiality and input data privacy, and achieve uninterrupted model controllability, we propose a contract-based model authorization framework called DeepContract. This framework enables model owners to deploy their models on the user side for local inference without revealing original model weights. Moreover, it allows them to grant and revoke the right to use their models at any time. Specifically, we propose a generic model encryption method that significantly outperforms the state-of-the-art method in both security and efficiency. Leveraging the integrity verification in the Trusted Execution Environment, contract-based and verifiable enclave codes generated by DeepContract can perform controlled inference with the distributed encrypted model on the user side. Our extensive evaluations show that DeepContract can achieve secure and efficient controllable model authorization for the pre-signed contract.

# 1 INTRODUCTION

Deep learning (DL) techniques have achieved remarkable results in various fields. However, training high-performance DL models requires significant upfront investment from model owners. This includes preparing high-quality datasets, as well as investing a substantial amount of time and resources in training. Consequently, well-trained DL models have become recognized as valuable intellectual property (IP).

To fully capitalize on the value of DL models, model owners are often willing to offer their models as services, as long as they can safeguard their IP rights and receive the corresponding revenue. A line of popular solutions is Machine Learning as a Service (MLaaS) [41]. In this scenario, a model owner deploys his/her models on a cloud server for on-demand inference by users, reducing the overhead of mobile devices by leveraging cloud computing resources. While MLaaS can protect the model owner’s IP as long as the cloud server is trusted, it raises serious privacy concerns. This is because all users must send their input data to the cloud, which may leak sensitive information such as personal identities, medical records, and private photos. To address this issue, another line of work focuses on protecting the privacy of input data during the inference process. Various methods based on homomorphic encryption (HE) [4, 5, 11, 18, 22, 33] and secure multi-party computing (MPC) [7, 23, 34, 35, 38–40] have been proposed to protect user privacy. However, the computational and communication costs incurred by these methods are prohibitive, leading to unacceptable latency for real-life applications. Some methods [19, 28, 45] utilize the Trusted Execution Environment (TEE) to support efficient model inference while preserving the confidentiality and integrity of user data. However, they do not consider the confidentiality of the model itself, and thus cannot protect the IP of model owners.

In order to protect the IP of model owners, a series of works have explored active authorization control [2, 6, 16, 30]. These approaches ensure that the model is only accessible to authorized users by modifying the model and granting correct usage to authorized users. However, existing methods can only prevent models from being stolen by unauthorized users and cannot restrict the use of authorized users. Once the model is distributed, the model owner loses subsequent control over the authorized model, which is equivalent to selling the entire model outright. Additionally, such model authorization can be easily transferred and abused by dishonest users since the authorized model is a white box for them.

Figure 1: Controllable authorization of DL models.

There is still a lack of a controllable model authorization mechanism that can efficiently protect both the model confidentiality of the owner and the privacy of users’ input data. To address this gap, we aim to design a privacy-friendly controllable authorization mechanism in this work, without relying on any trusted third party. As shown in Figure 1, the mechanism should allow model owners to deploy their models on the user side for local inference without revealing the original model weights. In this way, users do not need to transmit any input data, and model owners can well protect the model confidentiality. More importantly, model owners can grant and revoke the right to use their models at any time.

To achieve this ambitious goal, we need to address several critical challenges. First, it is difficult to deploy the model on the user side in a way that guarantees both confidentiality and efficient execution of the model. Although directly encrypting all weights of the model [2] can protect the whole model, it inevitably brings an unacceptable computational overhead. Selecting critical weights for encryption [43] can significantly reduce the computational overhead, but suffers from direct exposure of the encrypted region of the model and statistics analysis attack that restores the encrypted weights. The state-of-the-art (SOTA) model encryption method Chaotic Weights (ChaoW) [30] addresses the statistics analysis attack on the encrypted model. However, it imposes restrictions on the shape of the encryption area and thus is vulnerable to the finetuning attack which allows attackers to restore the encrypted model with a tiny fraction of the dataset, as described in §5.1. Therefore, existing model encryption methods cannot simultaneously meet our requirements of model confidentiality and low computation overhead. Second, model decryption is an unavoidable step when performing the model inference, but the decrypted models can be easily stolen on an untrusted device during the inference process. It is impractical to store the entire decrypted model within TEE since the protected memory area (e.g., 128 MB for Intel consumer CPUs) is far less than the size of many DL models. For example, VGG-16 [42] requires ≈ 520 MB of memory and even AlexNet [27] requires ≈ 230 MB of memory. Therefore, performing the inference with straightforward encryption within TEE incurs significant overhead to frequently swap in/out pages from the protected memory from/to the unprotected memory, resulting in abundant additional encryption/decryption of data, which is unacceptable for resourceconstraint devices. Third, the controllability of authorized models should be uninterrupted and inescapable on remote devices to prevent surreptitious abuse by authorized users. The model owner needs to maintain the connection with the decrypted model to revoke the usage right. However, all existing model authorization works [2, 6, 16, 30, 43] fail to offer such controllability after the model distribution, which can be exploited by dishonest users.

To address the above challenges, we propose a novel framework, named DeepContract, to support controllable authorization of DL models without any trusted third party, which strikes a balance among model confidentiality, model controllability, and inference latency. First, we propose a generic model encryption method, achieving efficient encryption while resisting both brute-force attacks and fine-tuning attacks. We tailor this encryption method to be suitable for model inference inside TEE, which requires no extra memory space, with breakneck decryption speed and transmission-friendly keys. Second, DeepContract employs memory-efficient decryption and inference to reduce memory usage by dynamically loading needed model weights and promptly releasing feature maps after being used for the pre-calculated times. The authorized model is only decrypted and executed within the user’s protected memory using the transmitted key, which protects the decrypted model from unauthorized copying or tampering by other parts of the device. Third, we leverage the integrity verification of enclave codes within TEE, such as Intel Software Guard Extensions (SGX) [12], to ensure that the remote device performs a series of operations as intended by the model owner. DeepContract generates user-specific enclave codes based on the pre-signed contract and distributes them to the user. Pre-generated and verifiable enclave codes ensure that the user is required to maintain communication with the model owner to perform controlled inference and terminate the service on schedule.

We have successfully implemented DeepContract and evaluated its performance using well-known Deep Neural Networks (DNNs) and datasets. Our model encryption method is 8.9x and 2.4x faster than the straightforward encryption method DeepLock [2] and the SOTA encryption method ChaoW [30], respectively. It also enables encrypted models in DeepContract to defend against bruteforce attacks and fine-tuning attacks. Furthermore, when compared to the SOTA in-enclave inference framework Occlumency [28], which neither protects model weights nor supports controllable authorization, DeepContract provides model confidentiality and controllability with only 8%-23% slower inference speed at different security levels.

The main contributions of this paper are as follows:

• We propose a novel contract-based model authorization framework, which, to the best of our knowledge, is the first work that achieves both confidentiality and controllability of authorized DL models.   
• We propose a generic model encryption method, which significantly outperforms the SOTA encryption method ChaoW, addressing the deficiencies in security and applicability. Furthermore, we devise a credible mechanism to control the

use of the authorized model with arbitrary periods, thereby preventing illegal copying, redistribution, or abuse.

• We evaluate DeepContract with representative DL models and the results demonstrate its superior security, effectiveness, and practical value. We conclude that DeepContract is applicable on resource-constrained devices wherever the TEE-based inference can be performed.

# 2 RELATED WORK

# 2.1 Active Authorization Control

Software-based Methods. Chen et al. [9] introduce the anti-piracy transform module, which can only be accessed by authorized users to use high-accuracy models. However, such a simple conversion structure is difficult to resist input-output pair attacks and is easily stolen by authorized users. ChaoW [30] exchanges the weight positions to avoid plaintext DNNs stealing during the inference stage. It cannot prevent leakage of the original model since the decryption method is accessible to users. DeepIP [16] adds additional passport layers to the original model. The model maintains correct inference performance only when genuine passports are fed to it, but passports after distribution can be illegally transferred and abused. Those software-based approaches are designed to prevent unauthorized use by modifying the model in various ways to degrade the model’s performance. They generally require prohibitive retraining before the authorization of each new DL model. Moreover, once authorized users have mastered the corresponding usage methods, they can still resell the authorized models without any control.

Hardware-based Methods. DeepAttest [8] embeds a specific fingerprint in the model before distribution, utilizes the TEE of clients to extract the fingerprint from the running model, and compares it with the preset one for authentication. Since the model is white-boxed, the method protects the integrity of the model rather than confidentiality. HPNN [6] leverages the trustworthy hardware as a root-of-trust to conduct obfuscated DNN inference. However, there are no corresponding measures for it to manage the distributed hardware and terminate existing authorizations.

Existing active authorization control methods are limited to onetime authorization, which only prevents unauthorized users from stealing models but does not provide protection against dishonest authorized users. Once authorized by the model owner, users have complete control of the model, enabling them to abuse it and even make secondary sales without restrictions.

# 2.2 Two-party Secure Inference

A secure inference protocol allows users and model owners to interact, enabling the user to obtain inference results without revealing any private information to either party. Many efforts have been made to implement these guarantees through the use of secure two-party computation [23, 32, 34, 35, 38]. However, all of these two-party methods assume that both the client and server are semihonest and cannot resist attacks from malicious users. Ryan et al. have proposed a model-extraction attack [29] against secure inference protocols that allows a malicious client to extract all the model weights with fewer queries, thereby compromising the security of these protocols. What’s more, the prohibitive computational and communication costs of these protocols make them still a long distance from practical applications, especially for applications with strict real-time requirements, such as intelligent education [49] and medical diagnostics [24].

# 2.3 Model Watermarking

Model watermarking [1, 13, 15, 20, 31, 46, 48] involves the incorporation of an owner-specific mark into a model during the model training phase. This mark can be extracted by the model owner using a predetermined method during the model authentication phase, which serves as proof of ownership. Model watermarking is a reactive approach and can only be employed once an infringement has been detected. However, it is impractical for the model owner to access the suspect model to collect evidence, as the pirate may use it privately or encapsulate it as an API to offer business services. Even if the model is accessible, there is a significant risk that the watermark will be removed or overwritten, rendering it unextractable, which is unacceptable to the model owner.

# 3 PROBLEM AND THREAT MODEL

Controllable model authorization involves two parties: the semihonest model owner and malicious authorized users. The model owner needs to provide inference services on the user side. To protect ongoing profits, the model owner aims to deploy the encrypted model ??′ on the user side so that authorized users can conduct controlled model inference for a specified period ?? or a limited number of times ?? , but cannot access the original model ??.

The security objective of DeepContract is to protect the model confidentiality and controllability without revealing users’ input data. The model owner trusts the enclave with TEE on the user side. Authorized users trust the privacy-preserving inference services provided by the model owner, as the distributed enclave codes are visible and auditable for security. In our threat model, authorized users are considered as potential adversaries whose aim is to obtain unrestricted access to the original model. As shown in Figure 1, authorized users may employ various attacks, including brute-force attacks and fine-tuning attacks, during the deployment process to crack the encrypted model. Besides, they may search for vulnerabilities in the inference process to steal the model once it is decrypted. Additionally, they may also explore potential methods to bypass the termination process. Since the model inference is conducted on the user side, the user data does not leave the device and remains under control. Therefore, this paper focuses on model confidentiality and controllability because authorized users have sufficient incentives to steal or hack the model with relatively little cost.

We assume that TEE and SGX enclaves in it are the only trustworthy components on the user side, and they are safe both in terms of computation and memory footprint. The communication channel between the model owner and the enclave is secured using RA-TLS [25] protocol, which is based on the hardware-backed cryptographic keys stored inside TEE. Note that the SGX side-channel attacks [10, 47] are out of scope for this paper since there have been complementary mechanisms [26, 36] to prevent them.

# 4 DEEPCONTRACT DESIGN

# 4.1 Design Goals

We designed DeepContract to achieve the following goals:

Model confidentiality. The primary goal is to prevent the original model from being exposed to authorized users throughout the authorization process, as such exposure may lead to illegal copying and redistribution.

Model controllability. DeepContract should control the use of the authorized model in the inference and termination process. Authorized users are only permitted to conduct inference for a specified period or a limited number of times as agreed upon in the contract, thus preventing surreptitious abuse of the model.

Minimal latency and resource consumption. DeepContract requires minimal inference latency and resource consumption while ensuring model confidentiality and controllability. It is crucial for the imperceptibility and applicability of DeepContract, particularly in mission-critical domains such as healthcare and traffic.

# 4.2 System Overview

Figure 2 depicts the architecture of DeepContract, which generates the encryption key and enclave codes from the pre-signed contract on the model owner’s side while performing controlled inference on the authorized user’s side. The dotted lines between the two endpoints in the figure represent early deployment before the startup request, while the solid lines represent interactions during the authorization period. DeepContract provides libraries on the owner side to generate the encryption key and enclave codes, encrypt the original model, interact with the authorized user, and enforce uninterrupted usage control. On the user side, the initialization involves loading the pre-generated enclave codes, creating the enclave within TEE, and establishing an attested secure channel with the model owner. The decryption key and pre-computed hash values of model weights are transmitted between the model owner and the enclave using the RA-TLS secure protocol.

Occlumency [28] is a solution to perform DL inference in the hardware-protected enclave of a cloud platform, aiming to minimize the computational burden on mobile devices. The authors assume that developers commonly utilize pre-trained public models directly, thus they protect user privacy rather than model confidentiality. As a result, Occlumency places the entire original model in unprotected memory and solely verifies the model’s integrity after weight loading to ensure accurate model inference. This disregard for model confidentiality leaves the original model vulnerable to effortless copying and redistribution by attackers. However, in the scenario of model authorization, the authorized model embodies the IP and subsequent profits of the model owner. Therefore, our primary concerns and distinct advantages over Occlumency lie in the confidentiality and controllability of deployed models.

We address the deficiency of Occlumency through a credible form of end-to-end interaction that involves generating contractbased enclave codes on the owner side and conducting controlled model inference on the user side. With this system design, Deep-Contract achieves all of its design goals. By presetting the security level and implementing robust encryption measures for the authorized model, DeepContract effectively mitigates the risk of model theft and ensures the protection of model owners’ profits. Through careful management of model decryption keys and the utilization of pre-generated enclave codes for controlled model inference, Deep-Contract empowers the model owner with uninterrupted model controllability. With memory-efficient decryption and inference, DeepContract notably reduces latency and resource consumption, satisfying the response-time requirements of real-life applications.

# 5 MODEL CONFIDENTIALITY

In controllable authorization, we use SGX-based inference to ensure confidentiality and correctness during the inference process. However, before the authorized model is loaded into TEE, its confidentiality also needs to be strictly protected because the remote device is untrusted. The loss of the model confidentiality may lead to irreparable damage to the business of model owners and an unintended exposure of their vulnerability. To eliminate potential threats to controllable authorization during the deployment process, we analyze the limitations of the SOTA model encryption method and propose a generic encryption method that satisfies our encryption requirements.

# 5.1 Encryption Requirements

For the model owner, the encrypted model for controllable authorization needs to meet the following requirements: i) The encrypted model should lose its original functionality, while ensuring that there is no loss of inference accuracy after decryption. ii) The model decryption has to be compatible with the SGX-based DL inference process, and the additional overhead incurred has to be as small as possible. Since it is impractical to store the decrypted model within TEE due to the limited memory, the model decryption should be layer-wise to pipeline with the model inference. iii) The encrypted model without the correct key should not be crackable with reasonable time and effort cost.

We argue that encrypting all weights of the original model with common encryption algorithms (e.g., AES or RSA) to protect model confidentiality is incompatible with our encryption requirements. These algorithms are not exclusively designed for floating-point numbers or model weights. Directly encrypting all model weights as strings would inevitably result in a lot of computational and storage redundancy. Alternatively, multiplying floating-point numbers by a certain multiple to encrypt integers would result in some precision loss of the decryption result. Such a straightforward application would turn the encrypted model into a large number of ciphertexts and keys with dramatically increased length. It would incur intolerable latency and memory overhead after the encrypted model is loaded into the enclave, as the decryption of these ciphertexts is computationally intensive and completely independent from the model inference process. Given the limited memory capacity of the TEE, numerous weights will be repeatedly encrypted and decrypted due to page swapping, which further magnifies the additional overhead imposed by the encryption method. Furthermore, if the keys used vary for each parameter, managing and transmitting these enormous amounts of keys will incur extra complexity and latency. We compare the performance of straightforward encryption with convolutional mapping encryption in §7.2, demonstrating that straightforward encryption is not a suitable encryption method for achieving controllable model authorization.

Instead of using common encryption algorithms to encrypt the weight values directly, the SOTA model encryption method ChaoW [30] adopts Arnold’s Cat Map (ACM) [14, 37] to exchange the positions of convolutional kernels to confuse the model weights. The exchange of convolution kernel positions in selected layers is compatible with the layer-by-layer execution of SGX-based model inference and such mapping encryption makes encrypted models require no additional storage space. However, it has some non-negligible limitations:

Limited encryption area. Due to the nature of the ACM algorithm, the encryption area of ChaoW must be square. Namely, the encryption range ?? needs to satisfy $S \le \operatorname* { m i n } ( C , N )$ . Therefore, a large difference between ?? and ?? will lead to a small encryption range of the convolutional layer by ChaoW. For example, the shape of the third convolutional layer of VGG-16 is 64 × 128 × 3 × 3, and ChaoW can encrypt at most half of the convolutional layer weights. We evaluate model accuracy as a metric for model performance, defined as the number of classifications a model correctly predicts divided by the total number of predictions made. After encrypting only half area of the layer, the accuracy of VGG-16 on the CIFAR-10 dataset decreases from 92% to 45%. However, the model accuracy can be effortlessly restored to 90% by fine-tuning the encrypted model with only 5% of the training dataset. Besides, Figure 3 shows that a small encryption range can degrade the encryption effect severely.

Likely fine-tuning restoration. According to the key search algorithm of ChaoW, it typically requires encrypting only one or two layers to achieve a satisfactory encryption effect. A smaller number of encrypted layers reduces the overhead of encryption and decryption but increases the risk of the encryption layers’ location being guessed by adversaries. We propose a specific attack method using a tiny fraction of the dataset as follows. Initially, we assume that only a single layer is encrypted, traverse each model layer in turn, and freeze other layers for fine-tuning. If the model accuracy is significantly improved, we consider the encryption layer to have been found. Similarly, we can traverse each encryption strategy in this way for two-layer encryption and so on. As described in [30], the number of encryption layers in the ChaoW method is generally less than three, making the complexity of the traversal search attack tolerable relative to training a new model from scratch. # 5.2 Encryption Method

The encryption requirements of controllable authorization and the limitations of existing methods motivate us to design a dedicated method for the encryption and decryption of authorized models. Therefore, we propose a generic mapping encryption method inspired by Baker’s Map [17]. Unlike ChaoW, our method does not impose any restrictions on the shape of the convolutional layer. For a convolutional layer of shape $C \times N \times k \times k .$ , we treat each convolution kernel as a point in a two-dimensional plane. Let $N _ { a }$ and $N _ { b }$ denote the smaller and larger of the first two dimensions (?? and ?? ) of the layer’s shape. As shown in Figure 4, the encryption and decryption of a convolutional layer proposed by us are equal to the mapping transformation of points in the rectangle with width $N _ { a }$ and length $N _ { b }$ , where each point represents a ?? ×?? convolution kernel. We detail our model mapping encryption method in Algorithm 1. To encrypt a convolutional layer, we first divide the $N _ { a } \times N _ { b }$ rectangle into ?? large rectangular blocks in the horizontal direction, where each rectangular block has $N _ { a } \times n _ { i }$ points. We then divide each large rectangle into multiple small rectangles with a length of $q _ { i } = N _ { b } / n _ { i }$ such that the points in each small rectangular block can fill an entire row of the original rectangle. Finally, we rearrange the points in each small rectangular block into a row from bottom to top and left to right, and traverse all small rectangular blocks in the same order. The decryption of the encryption layer is the inverse process of the above algorithm for its reversibility.

# 5.4 Attack Analysis

# 6 MODEL CONTROLLABILITY

To eliminate potential threats to controllable authorization during the inference and termination process, we devise two techniques: contract-based code generator and controlled inference engine. While ensuring model confidentiality, our design for memory-efficient decryption and inference within TEE makes model authorization for a specified period or a limited number of times possible.

# 6.1 Contract-based Code Generation

Unlike two-party secure computing, which assumes that users follow protocols honestly, malicious authorized users in controllable authorization may perform arbitrary actions on remote devices. To ensure that the remote device performs a series of operations as intended by the model owner, we devise a contract-based code generator that can generate verifiable codes following the pre-signed contract. Our key idea is to leverage the hardware-protected enclave within TEE to execute our pre-generated codes. Pre-generated and verifiable enclave codes guarantee that the user must be in contact with the model owner to efficiently perform controlled inference and terminate the service on schedule.

As shown in Figure 5, the generator initiates the process by producing the authorized keys and user inference codes for the authorized user, taking the authorization period, verification interval, and security level as inputs. The security level of DeepContract is adjustable, including intolerable cracking time $T _ { s e t } .$ , unacceptable restored accuracy $\sigma _ { u } .$ , and defensible proportion of leaked dataset ??. The user inference codes involve interaction with the owner and controlled model inference for the specified period or counts. Two measurement values of the user’s enclave, MRENCLAVE and MR-SIGNER, are finalized as the attestation evidence for code integrity after the generation of user codes. They provide the identity of the enclave code and the identity of the authority over the enclave, respectively. Finally, owner control codes are generated by feeding the product ID and measurement values, which can authenticate the user and verify the authorization period while ensuring the corresponding user codes are not tampered with.

Using the generated keys, DeepContract can perform the mapping transformation of the convolution kernels’ position to achieve the encryption of the authorized model. Along with the encrypted model, the enclave codes are distributed to the authorized user in the deployment process. DeepContract can flexibly balance the cost and security level of model authorization by adjusting the required input parameters. With enclave codes generated for the specific device and contract, the model owner can adaptively choose different trade-offs according to the application scenarios and local resource conditions, without spending extra computing or storage resources to maintain multiple authorized models or adopt different authorization strategies.

# 6.2 Controlled Model Inference

As shown in Figure 2, the model owner initiates remote authentication once receiving the startup request. After confirming that the user’s device is trusted, the integrity of user codes will be verified. If the code measurement changes (e.g., malicious tampering), there is no guarantee that the model will be decrypted and executed safely. Consequently, the model owner will reject the startup request to ensure the security and integrity of the system. After remote authentication and code integrity verification, an attested secure channel between the model owner and the user’s enclave is established to transmit the decryption key and pre-computed hash values of the encrypted model.

The enclave with the pre-generated codes will perform controlled model inference on the user side, as shown in Figure 6. We summarize the process in the following steps: on-demand weight loading, model checking, weight decryption, memory-efficient inference, and termination comparison. Such a union structure enables the enclave to efficiently perform controlled inference even with limited protected memory. The on-demand weights loader dynamically loads the needed encrypted weights layer by layer into the enclave. The model integrity and legitimacy checker can prevent malicious users from tampering with the model and testing out the decryption key by using the pre-computed hash values before the weight decryptor. The dedicated decryptor requires little extra memory and latency due to our proposed encryption method in §5.2. The decrypted weights of each layer are already ready in the ring buffer just before the inference engine starts to execute that layer so that the inference engine does not need to wait for the weight decrypting. After the execution of a layer is finished, the corresponding buffer is released so that it can be reused to load the next layer. It is worth noting that DeepContract identifies how many future layers access a feature map and calculates the usage of each feature map for the authorized model before the inference process. Therefore, the enclave stores the feature map only for the minimum required duration and releases it after being used for the pre-calculated times in the inference process. The memory-efficient decryption and inference ensure that DeepContract can run large DL models on memory-constrained devices without any accuracy loss at a lower overhead. As the inference is finished, the enclave promptly uploads the current usage status to the model owner and compares it with the preset value to determine whether to terminate the service. In DeepContract, the time-based scheme gets the trusted time of SGX while the counting scheme uses the monotonic counter of SGX. Only when the check succeeds can subsequent inference be performed as expected. In case of any breach of the contract by authorized users, the model owner can instantly update the comparison value to terminate the authorization through the established secure channel.

There are two additional designs to ensure that the termination process of DeepContract is inescapable: i) Minimum verification interval: There are many vulnerabilities if DeepContract is implemented directly as a common periodic authorization. For example, if the client is disconnected from the network and loses connection with the model owner, the inference service in the enclave will continue, and there is no way for the model owner to subsequently control the model. By adding a minimum verification interval to DeepContract, the model owner can ensure that the running status of the user’s enclave is continuously monitored. We define the verification cycle as the process of conducting the necessary verification and performing multiple inferences. In a verification cycle, DeepContract performs the model integrity and legitimacy check, as well as the usage status upload, only once. Even if the user becomes malicious, they cannot interfere with the inference process occurring inside the enclave. Any malicious behavior will be detected by DeepContract at the beginning of the next verification cycle. ii) Inference interruption and continuation: The enclave cannot always be continuously executed since interruptions may occur during a long authorization period. Therefore, DeepContract creates an authorization status record table on the owner side and saves the number of used times to ensure the continuation of interrupted services. If the authorized user has not previously saved the number of times used, the model owner will reject the new startup request. All these designs impose little additional burden on memory-constrained TEE and integrate decryption and inference organically.

# 8 CONCLUSION

We propose DeepContract, a contract-based model authorization framework, which protects user privacy throughout the end-to-end offloading and leverages user-specific enclave codes to perform controlled inference. We use Intel SGX for implementation, but DeepContract can be easily migrated to other platforms (e.g., OP-TEE on TrustZone), as we have addressed the crucial issues of model confidentiality and model controllability, supporting efficient model decryption and inference simultaneously within TEE.
